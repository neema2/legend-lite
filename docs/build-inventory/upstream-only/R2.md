## 0. The wiring (it decides what "ours" means here)

- Both generators link the COMMITTED core: `:generators` deps `//core` (spec/BUILD.bazel:56-68). `:claims` is
  compiled against `//core` too (:74-86). Every `Pure.*`, `Prelude.*`, `SystemMetamodel.*`, `CoreFn.*`,
  `NameResolver.CORE_IMPORTS` and `Claims.*` value below is therefore the committed core's value, not the bump's.
- gen_prelude also reads core's Java as TEXT: arg 3 is core/src/main/java, with Pure.java swapped for
  gen_natives' output (spec/BUILD.bazel:451-469, override at :462). So the text Pure.java is the regenerated
  one, while the compiled `Pure.nativeFunctionsAt` is the committed one. That skew is real.
- gen_engine_handlers declares only Handlers.java as a src (spec/BUILD.bazel:316-328). Its other inputs come in
  through the classpath, so Bazel cannot see them as inputs. That includes the committed prelude.pure, through
  `Prelude.elements()`, which reads the resource at core/src/main/java/com/legend/builtin/Prelude.java:42.
- The prior dossier (bazel-plan/docs/build-inventory/generators/G1_dossiers.md:46-47,97-137) agrees on all of
  this. I re-verified each read below.

## 2. What an upstream-only prelude would be

**(a) Every upstream shape the spec defines in the covered packages.**
- legend-pure platform roots: already whole for classes and enums (PG:389-398). The only things holding shapes
  back are inputs #2 (6 enums), #9 (corpusDefined) and #10. 390 class/enum FQNs live in the 9 roots by regex,
  plus m3.pure's printed classes. The functions are whole except for the 245 claimed and 21 system-owned.
- legend-engine: ENGINE_SPEC_ROOTS hold 7,685 class/enum FQNs. The prelude carries 174 of them, so (a) for the
  engine side is about 44x the engine part. Many of those files sit behind parse walls in our parser (PG:875-878
  throws on a wanted file that does not parse, so this would fail loudly). It would also widen the boot layer
  that `Compiler.boot()` resolves and checks every process (Compiler.java:267-292). Its cache key hashes the
  whole source (Compiler.java:296-301). Boot cost grows with size; OPEN how much (settle by timing `boot()`
  with a prelude built over STDLIB_ENGINE_ROOTS, UF:142-147, versus today's).
- Consequences for the compiler:
  - Duplicate declarations versus Pure.java: the 6 hand enums would appear twice, once in
    `Pure.allNativeEnums()` and once in `Prelude.enumFqns()`. Both feed NameResolver PLATFORM_TYPE_FQNS
    (NameResolver.java:300-306). OPEN whether ModelContext refuses or first-wins; settle by deleting them from
    Pure.java (the "phase 2" Prelude.java:31-32 already intends this) and running the gates.
  - The platform-owned exclusion rule would have to move into core at boot. Batch 169 (PG:516-528) shows why:
    with the 245 bodies present, a bare `join`/`filter` resolves through the core imports to the library FQN
    and bypasses the platform's form.

**(b) "What the platform's Java itself needs at boot" (COMPILER_DESIGN_2026_09_25.md:111-125, §3.1).** Stated
without scanning Java, that set has three upstream-derivable parts and one part that is ours:
1. The types named by the signatures of the natives we implement. Derivable from upstream once membership is
   given: membership is ours (native-membership.tsv), the signature text is upstream. The generator already
   applies exactly this rule to engine natives (PG:448-500). These signatures are where the 38 Pure.java hits
   come from.
2. The types named by the system metamodel's Pure text (PG:268-327). That text is ours, but it is Pure source
   whose references resolve by the language's own rules, not by a grep of Java.
3. The closure of 1+2 (PG:502), which is upstream.
4. The residue: classes our Java names as constants (PlatformTypes, WalledBodies, Overloads, ContextReading, …).
   This is genuinely OUR decision, and a hand list of it is still an input of ours. Under tenet 5 it belongs in
   a registration, a "platform-required shapes" row set, kept out of the generator and verified by a test.

**Which parts are genuinely ours:**
- Ours, and to move out of the generator: membership of natives, the claims, CoreFn forms, the hand enums, the
  system metamodel, EXCLUDED_PACKAGE_PREFIXES, ENGINE_LIBRARY_FUNCTIONS, the LIBRARY/SHAPE lists and
  "Java-required shapes".
- Upstream-derivable: PLATFORM_ROOTS whole (upstream's own "core" is defined by PureRuntime.loadAndCompileCore
  per UF:137-141, so the root list itself can be stated in upstream's terms), the STDLIB_ENGINE_ROOTS, closure,
  the verbatim text, CORE_IMPORTS and section order.

**Concrete design.**
- gen_prelude emits the UPSTREAM LIBRARY: PLATFORM_ROOTS ∪ STDLIB_ENGINE_ROOTS (upstream "core"), every
  class/enum/function/native, closed. It applies no ownership, claims or Java scan. Its only checks are parse
  walls (pinned) and closure.
- Ownership becomes a boot-time join in core. `Compiler.boot()` (Compiler.java:277-285) already applies
  `SystemMetamodel.withoutSystemShadows`. Add one `withoutPlatformOwned(ParsedModel)` beside it, keyed on the
  main-side registries (RegistryKeys, CoreFn.parseNames, Pure.walledNativeFqns, NativeFn.families: the same
  sources CL:91-128 reads; Claims itself is test-scope, CL javadoc) or on the generated native-claims.tsv. It
  drops claimed-name bodies and catalog-FQN natives, and it records them so the DecisionProbe and a test can
  list them (today's footer lists become a test's expected output).
- The engine-side shapes outside "core" (core_relational's SQLExecutionNode, RelationalCSVData, …; 61 today)
  are what our Java and the system metamodel name. They enter through a hand-owned registration file (for
  example core/src/main/resources/com/legend/builtin/platform-shapes.tsv, one FQN plus a reason per row). The
  generator reads it as a SEED LIST, which is a hand input to a generator and so still ours. Alternatively,
  better under tenet 4, the boot layer loads those files as a second module from a hand manifest. A test
  (today's PG:331-356 scan, moved to core/src/test) fails when Java names an upstream FQN that neither module
  declares.
- Files that change: PG:331-356, 359-398, 427-440, 529-592 (delete the scan and the ownership logic);
  spec/BUILD.bazel:451-469 (drop `//core:main_java` and the Pure.java override, so the action reads upstream
  only); Compiler.java:277-285 (boot filter); Pure.java:339-356 (delete the 6 enums, or have the boot filter
  drop the prelude copies); Prelude.java:63-82 (FUNCTION_FQNS should be the post-filter set, because
  withoutPreludeShadows, Compiler.java:327-338, and NameResolver.java:328-345 consume it; a claimed-name body
  in the function universe would re-open batch 169); NameResolver.java:300-306, 322-345.

## 3. gen_engine_handlers

Inputs of ours (EHG:80-126):
- `Pure.all()` (EHG:82-84, 110-122) and `Prelude.elements()` (EHG:85-89), both through `SignatureMangle.mangle`.
  They fill column 3 (fqn): empty when no platform function has that id (EHG:100-105).
- `Pure.LITE_SURFACE` (Pure.java:559-563) and `Pure.Lite.PKG` (EHG:110-123) produce the 6 `lite` rows (columns
  1-4 entirely ours).
- Columns 1 (name) and 2 (id) come from Handlers.java alone (EHG:53, 65-78).

Measured on the committed tsv (838 lines; 830 engine rows, 6 lite):
- For all 668 filled engine rows, `fqn == package(id) + "::" + name`. The fqn column is a pure function of the
  upstream columns. Our only contribution is the empty-or-filled bit (162 empty).
- 358 of the filled FQNs are Pure.java natives, 12 are declared only in prelude.pure, and 2 are matched by
  neither text grep (boolean::is, variant::convert::toJson; OPEN, probably catalog entries built
  non-textually).
- So the output depends on the committed prelude, which is another generated file: a two-run convergence
  (G1:116-137).
- Consumers: `EngineHandlers` (core/.../builtin/EngineHandlers.java:37-65) and `fqnsOf`, which feeds BareNames
  tier ENGINE (core/.../compiler/BareNames.java:57). That reaches NameResolver.java:1758 and
  FunctionCompiler.java:45; DynaFnGenerator.java:105-119 (a GENERATOR reading the committed tsv);
  EngineHandlersTest. `idsOf`/`names()`/`undeclaredIds()` are used only by EngineHandlersTest.

**Upstream-only design (feasible, measured):**
- Emit `name \t id \t fqn` with fqn = package(id)::name for every row, no `source` column, no lite rows. EHG
  then needs no core classes: drop the `//core` dep, or split EHG into its own library.
- `EngineHandlers` static init (EngineHandlers.java:37-65) joins at class init. `FQNS` keeps a row's fqn only
  when the platform declares that FQN (`!Pure.nativeFunctionsAt(f).isEmpty() ||
  Prelude.functionFqns().contains(f)`), then appends LITE_SURFACE by the same loop as EHG:110-122.
- Measured: filtering at FQN level instead of id level gives the SAME fqnsOf for every name. The unfiltered
  upstream table would add 71 new (name, fqn) pairs, and 0 of them name an FQN the platform declares; empty rows
  whose FQN is declared already appear under that name through a filled overload.
- `undeclaredIds()` (id-level) moves to EngineHandlersTest, which recomputes it with SignatureMangle.
- With that, BareNames, NameResolver, FunctionCompiler and DynaFnGenerator outputs are unchanged.
- This is also COMPILER_DESIGN §4 (docs/COMPILER_DESIGN_2026_09_25.md:283-286), which names "the handler
  surface's declared column" as a row source to move into the registry.
- Without the filter (raw upstream fqnsOf):
  - DynaFnGenerator would write undeclared FQNs into DynaFn.java (`pureFqns`, :105-118).
  - FunctionCompiler.functionsAt would let a GRAPH function at an undeclared engine FQN be reached by a bare
    call through the ENGINE tier. That is closer to upstream, but it is a behaviour change, so keep the filter.
- Experiment: implement the init join in a scratch copy and assert `fqnsOf(n)` equals today's for every n in
  `names()`.

## 4. Feasibility risks, each with what settles it

1. Boot size and cost for the prelude after the change (STDLIB_ENGINE_ROOTS added, ownership no longer applied
   in the generator). Settle: time `Compiler.boot()` and the corpus lane with the larger module.
2. Parse walls in the STDLIB_ENGINE_ROOTS. PG throws on a wanted file that does not parse (PG:875-878), but
   silently drops function files (PG:1443-1445). Settle: run `functionsIn` over those roots and count walls;
   make the function-file drop a pinned list rather than a silent skip.
3. The 6 hand enums duplicated. Settle: delete them from Pure.java and run //gates:local.
4. Ownership moved to boot changes the function universe that NameResolver sees unless Prelude.FUNCTION_FQNS is
   post-filter. Settle: the corpus roster diff (judge_lanes) with the filter in place.
5. Class-init order. EngineHandlers would read Pure and Prelude at init. Pure does not reference EngineHandlers
   (grep: no hits), and Prelude is already loaded by NameResolver.PLATFORM_FQNS first. Settle: a cold-start
   unit test that touches EngineHandlers first.
6. The committed-core skew (generators link //core, not the bump). It disappears for gen_engine_handlers once
   it needs no core classes. For gen_prelude it disappears once the scan and the claims leave. Settle:
   `bazel cquery 'deps(//spec:gen_prelude)'` shows no //core.
7. OPEN #11(c): whether the committed prelude's names, through PLATFORM_FQNS, change the closure. Settle: the
   empty-prelude diff run.
