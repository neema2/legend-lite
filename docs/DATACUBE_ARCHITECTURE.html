How DataCube runs

DataCube is a pivot grid for your data. Every click you make becomes a small Pure query. Two jobs follow: a planner turns the query into SQL, and a database runs the SQL. By default both jobs happen inside your browser tab, as WebAssembly. The modes below only change where each job happens.

What happens when you click

You group by a column, add a filter or expand a row. The grid describes what it now needs as a Pure query and asks two workers, one after the other. Nothing here leaves the tab.

  1. 1The grid writes a query. Your click changes the cube's state, and the grid builds the Pure query for the rows it needs to show.
  2. 2The planner compiles it. The same compiler legend-lite runs on a server answers with SQL and the type of every result column.
  3. 3The database runs it. DuckDB executes the SQL exactly as the planner wrote it, over the tables in the tab.
  4. 4Rows come back typed. Results arrive as Arrow columns. The plan says what each column is, so the grid never guesses a type.

Good for
Mapped data behind an engine's own connections

A page never changes mode behind your back. The planner is chosen once, when the page opens, and the status bar names it. If the chosen planner does not answer, the page says so and stops. It does not quietly fall back to another one.

There is a seventh arrangement with no screen: Python can run DataCube's own logic headless (grouping, totals, pivots, chart rules) in an embedded V8, with the native planner and Python's DuckDB. It is the Python picture with the top band removed.

Example: a Snowflake connection

A browser tab cannot open a Snowflake connection. There is no database driver in a page, and the credentials belong to a server. So the two jobs come apart: the WebAssembly planner keeps answering questions about the query, and a Legend engine does the running.

  1. 1Questions stay local. What columns a query has, whether a calculated column is valid, how a query reads as text: the planner in the tab answers with no network call.
  2. 2The query goes to the engine. One execute call carries the Pure query, the model and the runtime.
  3. 3The engine plans and runs. It writes Snowflake SQL and sends it over its own connection.
  4. 4Snowflake answers. It computes every value and returns rows to the engine.
  5. 5Rows come back typed. The answer names each column's type and the SQL that ran, as JSON or as Arrow.

Two limits today. The engine in this picture is legend-engine: legend-lite's own server does not open a Snowflake connection yet. And a grid on this path cannot be snapped, because there is no local copy to freeze the rows into.

Why WebAssembly, and why answers match

The planner in your tab is not a rewrite. It is the same Java source that runs on the server, compiled three ways. Tests run the same queries through each build and compare the answers, refusals included, so a cube plans to the same SQL wherever it is planned.

Both engines run in Web Workers, so compiling and querying never freeze the grid. The planner needs a browser with WebAssembly GC, and DuckDB needs WebAssembly exception handling. Current Chrome, Edge, Firefox and Safari have both. Only the Python page needs neither. All of it is served from the site's own vendor/ folder, never from a CDN, so it works behind a firewall.

Try each mode

In the tab

bazel run //datacube:serve

Prints a URL. Use Add a data source to open a CSV or Parquet file, or pick an example.

Plan on legend-lite

bazel run //core:server

Then add ?planner=remote to the page's address. Use ?planner=engine for a running legend-engine.

A Postgres database

bazel run //datacube:app -- postgresql://reader@host:5432/shop

Opens on the tables you may read, Live. Click Live to snap one into the tab.

A dataframe

import legend_lite as ll
cube = ll.show(df)

A tab opens, or the cube appears under the notebook cell.

A remote file

index.html?remote=https://host/trades.parquet

DuckDB reads it over HTTP range requests and pulls only the bytes a query needs.

Put it on a website

bazel build //datacube:dist

The result is a folder. Any static host will serve it. Turn on gzip or brotli.
