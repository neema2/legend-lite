claim ("*— S1 because …*") or, for the bucket rows, in the manifestation list. The distribution and
the exact rule used for the borderline calls:

|---|---|---:|---|
| **S1 CRITICAL** | silently wrong VALUES or TYPES delivered to a caller from ordinary, plausible source | 41 | A row is S1 if a **value or a Java carrier** that the caller receives is wrong — including "the right value under a type that cannot hold it" (D01, D03, D21) and "a row set that should not exist" (D23, D29-part, D79). Three deliberate severity decisions worth flagging to the reader, because a different auditor could
reasonably disagree:

* **D31 is S2, not S1**, even though it is by volume the largest defect in the audit (960 of A20's
  1010 oracle violations, 12 distinct manufacturing sites, four orchestrator repros). Returning
  `null` where the type says a value exists is a multiplicity violation; it becomes S1 only where a
  correct non-null answer was available (D27) or where the same query demonstrates the intended
  convention (D28).
* **D81 is S2, not S5**, although it is a divergence from a specification rather than a runtime
  misbehaviour. It is scored as an unchecked boundary because five of its members
  (`percentile`/`corr`/`covarPopulation`/`covarSample`/`stdDev`) are the *direct cause* of an
  executed `null`-under-`[1]`, and 21 more widen the public language surface with functions that
  cannot be ported anywhere.
* **D55 (bad SQL) is S3, not S1**, despite `GROUP BY <constant>` being a latent silent-wrong-answer
  hazard: no auditor produced a query where the folded constant *was* a valid ordinal, so the
  observed behaviour is an error, not a wrong answer. If someone lands that repro, the row moves to
  S1.
* **D99 is marked S4 (META) rather than forced into the scale.** It produces no wrong value, so it
  is not S1–S3; it is not really an inconsistency or dead code either. It is scored low and flagged,
  because by the brief's rules it *is* low — while being, in my judgement, the most actionable row
  in the table: it is the reason 15 of the 19 checked findings could exist in a green build.

## 3. ROOT CAUSES

Fourteen design gaps generate the 105 defects. Each is stated as one sentence, with the defects it
explains. A defect can appear under more than one root cause; the **bold** ID is its primary home.

**RC-1 — There is no runtime enforcement of any declared multiplicity, and the compiler
manufactures `[1]` claims from data it has already proven wrong.**
The type system can express nullability and does compute it correctly at the store boundary
(`StoreCompiler.java:108-110, 170-171`), and then twelve separate sites overwrite that answer with an
unenforced `[1]` — `trustOne` as identity, LEFT-join schema copying, aggregate return declarations,
`toOne` deletion, match/cast promotion. Nothing downstream ever checks a cell against its bound.
Explains: **D31**, D32, D33, D37, D40, D47, D27, D28, D07(part), D80, D92, D93, D94, D97(part).
A36 measured its full extent: **117 of 117 executable `[1]` cells deliver `null`, including the
perfectly-matched diagonal** — an `Integer[1]` property over a plain `INTEGER` column that merely
lacks `NOT NULL`. The only thing that makes a `[1]` property non-null is declaring the physical
column `NOT NULL`, which the mapping layer neither requires nor checks. **`[1]` is an annotation,
not a guarantee** — and A27 shows the DDL generator drops `NOT NULL` and `PRIMARY KEY` anyway.

**RC-2 — The mapping is the bridge between the Pure type world and the physical schema, and it is
unvalidated: it relabels instead of checking.**
`coerceColumnToDeclared` is a coercion table with a fall-through, not a compatibility check, and
three sibling entry points implement it differently. Everything downstream (G's inference, I's MIR
typing, J's render, K's decode, the wire) then trusts a claim phase E never verified — and phase I
is explicitly told (`tolerateRead`) not to complain about it.
Explains: **D01**, D10, D17, D22, D31a/j/k, D68, D78, D91.
A36's 874-cell matrix is the exhaustive statement: 100 silently unsound, 12 ICE, 108 sound, and the
only loud arbiter is a *generic constructor check that the normalizer's own coercions are built to
satisfy*. The `###Relational` DSL accepts 21 column spellings and rejects 64 common SQL ones —
`BOOLEAN` among them (V22) — and has no `TIME` spelling at all, so `StrictTime` and `LatestDate`
cannot be mapped to any column type.

**RC-3 — `cast` is a value conversion, not an assertion, and `Any` is a universal solvent that
re-enters it.**
`CastPolicy` decides by primitive family and converts on a narrowing; `crossKindRaise` is disabled
whenever either side is not an SQL primitive, which is exactly the `Any` the Typer hands out at
three sites and the `Any[0..1]` a late-bound grid hands out for any name asked for. The composition
is a zero-enforcement re-labelling channel.
Explains: **D02**, D03, D31h, D34(part), D64(part), D85.

**RC-4 — The inference kernel has no way to *reject*: no bounded quantification, no occurs check,
no freshening, a one-level substituter, and three widening escape hatches.**
`Type.TypeVar` is `record TypeVar(String name)` — the model cannot express a bound at all — so
`unify(T, anything, new Bindings())` succeeds, conflicting bindings widen to `Number`/`Any` instead
of failing, and `Bindings` is keyed by the raw variable spelling. Every "check" that runs with a
fresh `Bindings` against a variable formal is therefore a no-op.
Explains: **D36**, D04, D29, D09(part), D26.

**RC-5 — Reference safety is applied to some type positions and not others, and the subtype relation
has a bottom-type arm inside its recursion.**
Property, parameter and return positions throw `Unknown type`; the `extends` list and a generic head
do not. The `Nil` arm answers `true` before checking that the right-hand side is even a real type.
Together, a one-character typo silently detaches a class from its hierarchy, and three lines of
ordinary Pure collapse the whole relation.
Explains: **D37**, D38, D17, D19, D76.

**RC-6 — β-substitution is not capture-avoiding, and constant folding is done with Java semantics on
Java carriers.**
Two independent substituters (`SourceSubst.inlineLets`, `UserCallInliner`) rename nothing in the
cases that matter, and `StaticFold`/`NormalizeFolds` use `Long.sum`, `Object.equals` and the static
multiplicity where the un-folded path uses SQL's widening, SQL's numeric comparison and a real
`CASE`. The same source therefore has two meanings depending on whether it was inlined.
Explains: **D05**, D06, D09.

**RC-7 — Precision and scale are a first-class part of the decimal type and are lost, guessed or
re-inferred at six different places.**
`decimalType` counts only the scale; the `PrecisionDecimal` algebra that would derive a result's
`(p,s)` has zero callers; `NameResolver` drops the declared `(p,s)` entirely; `SqlTyping` re-infers
the literal's type by significant digits where DuckDB sizes by rendered width; `CsvSeed` pins every
decimal to `DECIMAL(38,9)`; and the decode strips `(p,s)` from the SQL type name.
Explains: **D21**, D22, D42, D43, D44, D76, D78(part), D66(part).

**RC-8 — There is no single owner for any typing rule; the same question is answered by 2–6
independent hand-rolled implementations that disagree.**
Six spellings of "is this many?", six primitive-subtype ladders, three `__|__` implementations, two
LUBs, two column-identity rules, two Decimal-normalization conventions (nine sites carry the arm,
four forget it), three CSV parsers, six Pure→SQL type mappings. Each pair is a latent behaviour fork
and several are live wrong answers.
Explains: **D65**, D64, D12, D13, D27, D71, D72, D78, D79, D89, D90, D47.

**RC-9 — The native catalog is a hand-written port that was never diffed against the language it
ports, and the only guard compares it to itself.**
183 of 721 signatures diverge from real FINOS Legend; the golden test renders `Pure.all()` and
compares it to a file generated from `Pure.all()`, with a renderer blind to the two multiplicity
forms that matter. Several "compiler" defects are catalog defects: the `[1]`-on-empty aggregates,
the unbounded `abs<T>`, the invented `first(set,count)`, the `⊆T`-less `over`.
Explains: **D81**, D71, D82, D31d, D36(part), D07.

**RC-10 — The lowering, the dialect layer and the decode each re-decide types the frontend already
decided, and no backend-neutral contract holds them.**
`SqlTyping` re-infers decimal literals, `CastPolicy` runs a family lattice, `Lowerer` does model
lookups to pick MIR shape, the decode keys on the driver's Java class rather than the declared type,
and SQLite has no dialect object at all — it inherits identity `normalize`, ANSI type names and
**DuckDB's function spellings**.
Explains: **D15**, D16, D20, D25(part), D30, D41, D51(part), D60, D69, D86, D87.

**RC-11 — Phase H (store resolution) invents `ExprType`s rather than deriving them, and the
post-H root type is what every public surface reports.**
The resolver builds join schemas by copying the right side's columns verbatim, stamps the serialize
envelope with the getAll's type, re-types a scalar `map` as a relation, and deletes `toOne`. Because
`plan()`/`execute()` report the post-H root, the frontend's correct answer is unobservable.
Explains: **D45**, D31b/c/f, D46, D74(part).

**RC-12 — The instruments that would have caught most of this are structurally disabled.**
`SqlTypeCensus.MISMATCH` is unreachable because reconciliation runs first; `carryThrough`'s
`tolerated` tag permanently mutes the label/wire tripwire for a column and is stamped at every
declared/column kind mismatch; `normalizeMeta` has no arm for H2's own `DOUBLE PRECISION` so the
census is *also* wrong in the other direction; `executePlan`'s decline tunnel and `SeedableLets`
catch `RuntimeException` and re-run bare, which will swallow the egress's own soundness walls; and
`exec.Column.multiplicity` — the field a consumer would use to check a bound — has zero readers.
Explains: **D68**, D83, D89, D66, D31(why it survived), D01(why it survived), **D99** — and D99 is
the top of this chain: of 1 671 test methods that run a query end to end, exactly **one** relates a
declared column type to the delivered Java carrier. The suite tests compile-time typing densely and
row values densely, and the seam between them not at all.

**RC-13 — Error discipline is a frontend property only; it collapses monotonically down the
pipeline.**
`AGENTS.md` states every user-visible error carries a `LegendCompileException.Phase`. That holds at
25 % internal throws in the parser and 15 % in the Typer, and reaches **100 %** in `sql/`,
`sql/dialect/`, `exec/`, `plan/`, `values/` and `protocol/` — 850 of 1 168 throw sites overall.
`NotImplementedException`, the most-thrown type (293 sites), is a bare `RuntimeException`. A sweep of
247 queries over the whole native surface produced 85 internal exceptions against 5 user-facing
errors, every one of which had passed phase G.
Explains: **D96**, D50, D53, D54, D56, D58, D59, D60, D62, D63, D97, D98.

**RC-14 — Three synthesized namespaces inside the compiler are user-writable, with no reservation
and no check.**
`$` in a synth FQN is a legal identifier character (`Lexer.isIdentPart`), `u_map__` is a legal column
prefix that `ResultShape` keys on, `_i<N>` is the inliner's fresh-name space and is not reserved
against callee bodies, `pk_0`/driver-PK names are not reserved against user properties, and `__|__`
is a legal user column name. Each is a silent hijack or a collision.
Explains: **D19**, D26, D05(part), D98, D64(part).

### 6b. Apparent contradictions between auditors — resolved

1. **"`plan()` and `execute()` agree on the root type" (V9; A20: 0 divergences in 18 000 queries)
   vs "they disagree" (A16 `fn::widen`; A12-H5 `serialize`).**
   *Resolved — different seams.* A20's oracle compares `plan().rootType()` to
   `execute().returnType()`; both are **post-H**. The divergences A16 and A12 report are between
   `Compiler.compileQuery` (**Phase G**) and the post-H surfaces, and the falsifier re-confirmed
   both (`\|fn::widen(1)` → `[G] Any[1]` vs `[PLAN-TYPE] INTEGER[1]`; `serialize` → `[G] STRING[1]`
   vs `[PLAN-TYPE] ClassType[biz::Emp] mult=[*]`). Both measurements are correct. The consequence is
   a **coverage gap, not a conflict**: no auditor's oracle compared G to post-H across a corpus,
   which is why D45 rests on hand-built cases. Recorded in §5c.

2. **"`->toOne()` over 0 rows raises correctly" (A02 VERIFIED SOUND) vs "`toOne()` is a no-op"
   (A20, A12-H1, V20, A24, A32).**
   *Resolved — three lanes, and the falsifier ran all three.* The **relation/collection** `toOne()`
   at a query root does emit `CheckedOne(CompactList(...))` and raises. The **`[0..1]`-stamped** arm
   falls to the default identity `return args.get(0)`. The **object-space** call is deleted outright.
   A24 sharpened it further: `toOne()` on a *column* does not assert (`SELECT t0.IN_V AS x` → `null`
   under `Integer[1]`) while the *literal* path does (`\|[]->toOne()` → `error(...)`). All auditors
   are right about the lane they tested. D31e/D31f name the broken lanes and D31 records the working
   one.

3. **"21 native signatures declare `[1]` and return nothing" (A07) vs "18 aggregates" (A14) vs
   "5 return-multiplicity narrowings" (A30) vs "135 declared-`[1]` results return NULL" (A24).**
   *Resolved — four counting bases, all correct.* A07 counts **registry signatures** shaped
   `[*] -> [1]` (21 signatures / 16 names). A14 counts aggregates **executed** over a zero-row
   relation that returned NULL (18 of 32 tried — a superset including `joinStrings`, `and`, `or`,
   `wavg`). A30 counts signatures whose return multiplicity is **strictly tighter than real
   Legend's** (5). A24 counts **scalar** results that returned NULL over the whole native surface
   (135). The sets overlap and answer different questions; D31d cites the first three, D92 the
   fourth.

4. **"`commonSupertype` has 0 non-upper-bounds over 441 pairs" (A03) vs "`LUB(Decimal,
   Decimal(10,2)) = Decimal(10,2)`, which is backwards" (A01).**
   *Resolved — different universes.* A03's 441-pair claim is over the **21 concrete** types, which
   excludes `PrecisionDecimal` pairs; A03 separately reports 6 commutativity violations over its
   42-type universe, **all** `PrecisionDecimal` — which is A01's finding. Both reports state their
   scoping.

5. **Three different root sites for the `Decimal → Double` carrier flip** (A10: `SqlTyping`;
   A01/A05/A17/A22: `Typer.decimalType`; A23: DuckDB's rendered width).
   *Resolved — all three, composed.* The Typer stamps a `(38,s)` the value cannot satisfy; the SQL
   layer independently re-infers `precision > 38 → DOUBLE`; and A23 showed the *real* switch is
   DuckDB's width `max(intDigits,1)+scale`, so a 38-digit **leading-zero** decimal also flips, and
   the intermediate `SqlType.Decimal(p,s)` is structurally illegal (`s > p`) for every `0.0…1`
   literal. D21 carries all three sites.

6. **A30's oracle vs the falsifier's inability to check it.** The falsifier confirmed the *runtime*
   half of A30's headline finding (`percentile`/`stdDev` declared `[1]` returning `null`) and
   explicitly declined the *upstream* half — "I have no independent legend-pure oracle either". A30
   does: two cloned repos at named commits, on disk, with a 24 368-declaration extractor. **Evidence
   favours A30**, and its provenance section is the reason. This is the one place in the audit where
   a load-bearing claim rests on a single auditor's checkout; the fix is cheap (re-run the extractor)
   and is the first thing a reviewer should redo.

7. **A02 "an association end `[2..1]` throws a raw `IllegalArgumentException`" vs A17-F12 "it is
   silently ACCEPTED".**
   *Resolved — complementary, at different phases.* V1-falsifier ran both: `compileModel` accepts it
   (`F12 assoc end [5..2] -> OK`), and the IAE fires only when a query navigates the end
   (`fal::P.all()->project(~[a:p\|$p.q.b])` → `IllegalArgumentException: upper (1) must be >= lower (2)`).
   Both auditors are right; D46 states both halves. This is the same phase-lateness pattern as the
   `DECIMAL(2,5)` correction above, and the two should be fixed together.

8. **"`exec.Column.multiplicity` has zero readers"** — A02, A09-F17, A25 and the falsifier all
   grepped independently (the falsifier over `core/src/main`, `core/src/test`, `pct/`, `nlq/`,
   `tools/`, `experiments/`). Four agreeing greps; no contradiction. Noted because it is the kind of
   absence claim worth quadruple-checking, and it was.
