# Bazel audit: the DataCube slice (datacube/BUILD.bazel, tests, src, tools, bench) plus pure-protocol and query-store

Audited at origin/main 16c8120d5 (2026-10-02)

**Slice:** `datacube/BUILD.bazel`, `datacube/package.json`, `datacube/tsconfig.json`, `datacube/pnpm-lock.yaml`, every file in `datacube/test`, a sweep of `datacube/src`, `datacube/tools`, `datacube/bench`, and all of `pure-protocol/` and `query-store/` (BUILD, src, test, package.json).

The biggest new problems:
- **N1.** Three committed files are generated by hand, outside any Bazel action.
- **N2.** Several tests read source code instead of running it, and they find it by walking directories relative to the working directory.
- **N3.** No test resolves runfiles the official way. Each one guesses runfiles paths by hand.
- **N4.** The npm scripts are a second, divergent test workflow.
- **N5.** Some tests hard-code timing.
- **N6.** Some tests depend on the clock, the time zone, or the locale.

Nothing in `src/` loads remote assets or extensions, so the risks there are confined to the tests.

Severity: **P0** = breaks hermeticity or correctness. **P1** = significant. **P2** = hygiene.

## Section 1: NEW findings

### N1. Committed generated files with no Bazel producer and no diff test (P1)
1. **`datacube/src/share/link-p1.ts` is generated by hand.**
   - The header (`:1-4`) says it was "Made once by datacube/tools/link-dictionary/make.ts". The recipe at `tools/link-dictionary/make.ts:13` is `bazel run //datacube:make_link_dictionary -- p2 > datacube/src/share/link-p2.ts`, a stdout redirect into the source tree.
   - `test/share-link.test.ts:91-94` pins only the sha256 of the committed bytes. Nothing checks that `make.ts` still reproduces p1.
   - This is the p1 instance of K4 (`link-p2.ts` does not exist yet).
   - The doc comment in `make.ts` disagrees with BUILD:237: one says `datacube/src/...`, the other `$PWD/datacube/src/...`.
   - **Fix:** run `make.ts` from a `js_run_binary` that writes `link-pN.gen.ts`. Add a `write_source_files` entry per frozen version, or a `diff_test` against the committed copy. Freezing then means "the tool's output for pN must never change", and the test enforces it. Delete the redirect recipe.
2. **`fixtures/saved-queries/*.json` are generated by hand.**
   - `make.mjs:4-6` says: "Regenerate: `java -jar bazel-bin/core/server_deploy.jar 18777 --query-store <empty dir> &` then `node fixtures/saved-queries/make.mjs`".
   - It uses host `node` and `java`, a fixed port 18777 (`make.mjs:10`), a background server, and paths relative to the repo root (`readFileSync('query/demo/models/...')`). It writes into the source tree. No target and no diff test exist.
   - These records are data for `//datacube:saved_queries_test`, `//query-store:share_test` and the query app.
   - The README (`:31`) says timestamps are incidental, so a diff test would need normalising.
   - **Fix:** an action that starts `//core:server` on port 0 with `--query-store $TMP`, POSTs the records, and writes normalised JSON. Then `write_source_files` with a diff test.
3. **`bench/README.md:102-107` relies on a hand-run `npm install`** (see N7).

### N2. Tests that scan source instead of running it, finding files relative to cwd (P1)
Each walks `src`/`demo`/`test`/`bench` with `readdirSync` relative to `chdir=datacube`. This needs a runfiles directory tree (it breaks with a manifest-only layout or `--nobuild_runfile_links`). Each one's declared data is a hand-kept glob that can drift from what it scans.

| File | What it scans | Gap |
|---|---|---|
| `test/state-guardrail.test.ts:12-23, 52` | `sources('src')` | |
| `test/config-readers.test.ts:24, 31-60` | `new URL('../src/', import.meta.url)` + `readdirSync` | |
| `test/menu-ids.test.ts:25-31` | reads `src/adhoc/mode.ts`, `src/ui/menu.ts`, `src/app.ts` | |
| `test/guardrails.test.ts:19, 87, 192, 235` | `src`, `demo`, and `existsSync('../wasm/differential.mjs')` in another package | |
| `test/portability.test.ts:23-38` | `ROOTS=['src','test','demo','bench']`, files ending `.ts .mjs .js .cjs` | BUILD:93-100 declares `tools/**` but tools is not scanned, so `tools/offer-facts/emit.ts` and `tools/link-dictionary/make.ts` are never checked (the comment at `:9-12` is stale). Any `demo/*.js` or `.cjs` is not declared, so it is silently not scanned. |

- `portability.test.ts:154-180` also writes `mkdtempSync(join(tmpdir(), ...))` instead of `$TEST_TMPDIR`. Cleanup runs as its own `it` ("cleans up"), so it depends on test order.
- **Fix:** move these to lint or analysis rules that take explicit `srcs` (an aspect over `:src`, or one `js_test` per rule with `args = ["$(rootpaths :src)"]`). Read paths from argv instead of directory walks.

### N3. Runfiles paths are guessed by hand; no runfiles library anywhere (P1)
1. **Every WASM consumer finds the planner by URL arithmetic** of the form `new URL('../../wasm/planner/', import.meta.url)`:
   - `test/catalog-builder.ts:5`, `test/saved-queries.test.ts:67`, `pure-protocol/test/lite.ts:13`
   - `test/{pivot-rows,json-read,cube-open,typed-values,live-snap}/*.ts:25-45`, `test/wasm-differential/compare.ts:30`
   - This assumes `_main/datacube` and `_main/wasm` sit side by side in a runfiles tree.
   - **Fix:** pass `$(rlocationpath //wasm:planner)` through `env` and resolve it with `@bazel/runfiles` (or `RUNFILES_DIR`/`RUNFILES_MANIFEST_FILE`).
2. **`test/wasm-differential/compare.ts:31`** reads `new URL('../../cube_jvm_answers.txt', import.meta.url)`. It assumes the `:cube_jvm_answers` output sits in the same directory as the sources (rules_js copy-to-bin). **Fix:** pass it as an arg or env with `$(rlocationpath)`.
3. **`test/live-snap/live-snap.ts:44, 85-86`** computes `RUNFILES = fileURLToPath(new URL('../../../', import.meta.url))` and joins `WAREHOUSE_BINARY`.
   - If the env var is missing it silently joins `''`, giving a directory, and fails later with an unclear spawn error instead of a clear refusal.
   - **Fix:** `$(rlocationpath)` plus a runfiles library, and fail fast when the variable is unset.
4. **`query-store/test/lite.test.ts:13-14`** builds `join(RUNFILES_DIR ?? TEST_SRCDIR ?? '', '_main', 'core', 'server')`. The repository name `_main` and the path are hard-coded; BUILD does not pass `$(rootpath //core:server)`.
5. **cwd-relative reads that assume runfiles colocation:**
   - `test/saved-queries.test.ts:24-28, 48`: `'../fixtures/saved-queries'` and `'demo/projects/trading'` (the `:projects` output).
   - `test/bundle-budget.test.ts:12-13`: `demo/bundle.js` and `demo/chunks-bundle`, outputs of `:bundle_bundle`.
   - `query-store/test/share.test.ts:10`: `../fixtures/saved-queries/...`.
6. **`test/{duckdb,snap,sorting,treeview,upload,group-derived,saved-queries}.test.ts` and the five in-node app tests** find DuckDB with `createRequire(import.meta.url).resolve('@duckdb/duckdb-wasm/blocking')`. That is acceptable through rules_js `node_modules`, but `@duckdb/duckdb-wasm` reaches the tests only transitively through `:src`. It is not declared on the tests that use it. Add `:node_modules/@duckdb/duckdb-wasm` explicitly, as the medium tests already do.

### N5. Hard-coded timing that can flake (P1/P2)
- **P1, `test/tile-layout.test.ts:381-386`:** `performance.now()` around 60 moves of a 200-tile layout, with `assert.ok(perStep < 16)`. This is a wall-clock threshold in a `size="small"` test.
  - **Fix:** tag it as a benchmark (`tags=["manual"]` or `exclusive`), or assert complexity (operation counts) instead.
- **P1, `test/live-snap/live-snap.ts:263-267`:** sets `expiresAt = now + 1.5s`, sleeps a fixed 2000 ms, and expects the timer (at 80%, so 1.2 s) to have refreshed through a real HTTP call. Under load the 0.8 s margin is thin.
  - **Fix:** inject the clock and timer into `WarehouseEngine` (`src/warehouse.ts:208`).
- **P1, `query-store/test/lite.test.ts`:**
  - `:16-23`: `freePort()` binds port 0, closes it, then hands the port to the server, a TOCTOU race.
  - `:38`: a 60 s startup budget inside `size="small"`, whose own timeout is 60 s, so Bazel kills the test before the clear error can fire.
  - `:43`: polls `/health` every 250 ms.
  - **Fix:** have the server bind 0 and print its port (as live-snap does), and set `size="medium"`.
- **P2, polling heuristics with time budgets:**
  - `test/pivot-rows/pivot-rows.ts:143-149` and `test/typed-values/typed-values.ts:103-109`: `quiet()` means "10 × 10 ms with nothing in flight".
  - `test/json-read/json-read.ts:125-131`: `until()` gives up after 10 s.
  - **Fix:** await the app's own completion promise.
- **P2, fixed sleeps:**
  - `test/grid-basics.test.ts:157`: 300 ms against a 250 ms timer.
  - `test/source-picker.test.ts:219, 240`: 300 ms against a 250 ms debounce.
  - `test/cancel.test.ts:76/79, 91/94`: a 5 ms vs 20 ms timer race.
  - `query-store/test/conformance.ts:173`: 5 ms between two creates, relied on for "newest first" ordering, at 1 ms clock resolution on the JVM server.
  - **Fix:** fake timers (`node:test` `mock.timers`) or injected clocks.

### N6. Clock, time-zone, and locale dependence (P1/P2)
- **P1, `test/upload.test.ts:139-158`:** expects `TIMESTAMPTZ '...+02'` cast to TIMESTAMP to give `'2024-01-02 01:04:05.123456'`, which assumes DuckDB-WASM's TimeZone is UTC.
  - It only passes because of the global `.bazelrc:15` `test --test_env=TZ=GMT` (or because DuckDB-WASM lacks ICU). It is not pinned on the target, and it is not in the Tokyo/New York lanes.
  - **Fix:** `env = {"TZ": "UTC"}` on the target, or set DuckDB's TimeZone explicitly.
- **P2, default-locale assertions.** Bazel does not pin `LANG`/`LC_ALL`, and Node's ICU default comes from the environment. A developer's `--test_env=LANG=de_DE` breaks these:
  - `test/app.test.ts:1230`: `/1,234 rows/`, from `src/app.ts:3615` `toLocaleString()` with no argument.
  - `test/export-model.test.ts:98`: `/showing the first 1,000 rows/`, from `src/export-model.ts:216`. Verified: `LANG=de_DE` produces `1.000`.
  - `test/export-doc.test.ts:163` passes only because n < 1000.
  - **Fix:** set `env = {"LANG": "C", "LC_ALL": "C"}` in one shared test macro, or pass explicit locales in `src`. Product code with locale-less `toLocaleString`/`toLocaleTimeString`: `src/app.ts:358, 1193, 1272-1275, 1415, 2719, 3614-3631`, `cube.ts:635`, `receipt.ts:49, 67, 73`, `warehouse.ts:322-323`, `snap.ts:218-219`, `ui/json-fields.ts:88`, `export-doc.ts:474`.
- **P2, the TZ lanes do not prove they ran in their zone.** `typed_values_{tokyo,new_york}_test` (BUILD:509-558) rely on `env = {"TZ": ...}`.
  - I verified rules_js writes `env` as an unconditional `export` in the bash launcher (`aspect_rules_js+/js/private/js_binary.bzl:306-312`, `_ENV_SET = "export {var}={quoted_value}"`), so it wins over `--test_env=TZ=GMT`.
  - But `typed-values.ts` never asserts the process zone (for example, `new Date().getTimezoneOffset()` is not 0). A launcher change, or Windows (no bash launcher), would silently turn all three lanes into GMT.
  - **Fix:** a one-line assertion on the zone in the test.
- **P2, wall clock in assertions:**
  - `test/save-dialog.test.ts:44-46`: `Date.now() - 2h`, expects "2 hours ago".
  - `query-store/test/conformance.ts:42, 67`: `Date.now()` and `Math.random()` for run ids. On the server lane this is needed because a store could persist, but it is a fresh tmpdir, so a counter would do.

### N8. Test isolation and order dependence (P2)
- **`test/pivot-rows/pivot-rows.ts:325-334`**, commented "LAST: it inserts rows every check above would see". R9 mutates the shared TRADES table, so correctness depends on `it` order within the file.
- **`test/snap.test.ts:77-100`** inserts, then deletes "so later tests see the original table". Shared mutable state.
- **`test/cube-fixture.ts:98-99`** runs `process.removeAllListeners('unhandledRejection'); process.on('unhandledRejection', e => unhandled.push(e))`.
  - This removes node:test's own handler, so every unhandled rejection in six tests is silently collected. Only `cube-transactions` "P2-114" checks it.
  - Affects cube-transactions, cube-lifecycle, cube-editors-app, cube-adhoc-shell, multi-cube and chart-tiles.
  - **Fix:** assert `unhandled.length === 0` in `afterEach`, and restore the listeners.
- **Global DOM mutation** (`globalThis.window`, `document`, `requestAnimationFrame`) that is never restored, in many files. Safe only because each Bazel target is its own process; under the npm script it leaks across files.
- **`test/live-snap/live-snap.ts:87`** creates `mkdtempSync(tmpdir())` and never removes it. It uses `tmpdir()` instead of `TEST_TMPDIR`. `after()` sends SIGTERM to the server without waiting for it to exit.
