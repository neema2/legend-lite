# Bazel audit of spec/, pct/, parser-equivalence/, testing/ and the Java under tools/

Audited at origin/main 16c8120d5 (2026-10-02)

**Slice:** every file in `spec/src`, `pct/src`, `parser-equivalence/src` (Java; resources skimmed), `testing/`, and every Java file under `tools/` (junit, java_run, teavm, par, bump, deps, reference, engine-runner, jars, postgres, generators, census), plus the BUILD.bazel/.bzl files of those packages.

The audit changed no files. Line numbers are 1-based and point at the audited checkout. Severities: **P0** breaks hermeticity or correctness, **P1** non-Bazel workflow, **P2** hygiene. Items K1–K19 were found in earlier passes; N-items are new.

## Section 1 — NEW findings

### N1 · P1 · Three test classes never run under any target

- **Evidence:** JUnit's console launcher only picks up classes whose names match `^(Test.*|.+[.$]Test.*|.*Tests?)$` unless a target passes `--include-classname`. Only `core/BUILD.bazel:384` passes it. Three classes in this slice have `@Test` methods and do not match:
  - `spec/src/test/java/com/legend/rcorpus/EagerCorpusCompileProbe.java`
  - `parser-equivalence/src/test/java/com/legend/equivalence/ProbeWireShapes.java`
  - `parser-equivalence/src/test/java/com/legend/equivalence/harvest/ZFixtureAdjudicationProbe.java`
- **What happens:** `--select-package=com.legend` (spec_tests) and `--select-package=com.legend.equivalence` (parser_parity) drop them without a word. Their javadocs still say "run with `-Dtest=…`" / "mvn test -Dtest=ProbeWireShapes", which is a Maven-era recipe. ZFixtureAdjudicationProbe would also read `Repo.out("engine-fixtures.jsonl")` left by an earlier run (`ZFixtureAdjudicationProbe.java:43-46`).
- **Fix:** turn them into `java_binary`/`java_run` diagnostics with declared outputs, or delete them. Add a guard test (or an aspect) that every class with `@Test` is selected by at least one `junit_test`.

### N2 · P1 · Java tools with no Bazel target, run by hand

- `tools/census/RenderCensus.java` has no target. `tools/census/render.sh:9-14` hard-codes `$(bazel info output_base)/external/rules_java++toolchains+remotejdk25_macos_aarch64/bin`, which only works on macOS arm64. It runs `bazel build`, copies the deploy jar with `cat > runs/…`, then runs `javac`/`java` by hand. Its input comes from `PctCaseRecorder` (`pct/.../extension/PctCaseRecorder.java:23-24`), which only records when `LL_PCT_CASES` is set; `tools/census/lanes.sh` sets it with `--test_env`.
- `tools/reference/RefImports.java` has no target. `tools/reference/README.md:40,94-96` gives a hand `"$JB/javac" … java -cp` recipe.
- `parser-equivalence/.../FixtureSweep.java` is a `main()` in the test tree with no target.
- **Fix:** give each a `java_binary` (or `java_run` action over declared inputs). Make the render census an action over the jars of `//core:core_tests` and the recorded cases. Delete `render.sh` and `lanes.sh`.

### N3 · P1 · TokenDump finds lexers through `java.class.path`; vocab.tsv is regenerated by hand

- **Evidence:** `tools/engine-runner/src/main/java/perf/TokenDump.java:37` splits `java.class.path`, and `:56-60` swallows every jar it fails to open. When Bazel's launcher falls back to a single manifest-only classpath jar — the case `tools/jars/defs.bzl:5-7` warns about — the dump finds nothing and still exits 0.
- **Impact:** the output, `tools/engine-runner/vocab.tsv`, is committed and read by `scripts/parser/keywords.py:103`. No action produces it and nothing diff-tests it.
- **Fix:** run TokenDump as a `java_run` over a `java_jars` list (as `GrammarCoverageCensusTest` already does via `Repo.listed`), fail when no lexer is found, and add `vocab.tsv` to a `write_source_files` with a diff test.

### N4 · P2 · engine-runner is a set of hand recipes

- `tools/engine-runner/README.md` documents `bazel run … $(grep … | awk …)` command lines and says the stress-corpus run is broken.
- `tools/engine-runner/.gitignore` still lists `target/` and `cp.txt` from Maven.
- No test target exercises the four binaries (`tools/engine-runner/BUILD.bazel:39-48`).
- **Fix:** add a `sh_test`-free `java_test` smoke target or `java_run` action per tool. Delete the README recipes and the Maven leftovers.

### N5 · P1 · Bump leaves the `@maven_runner` lock file stale

- **Evidence:** `tools/bump/Bump.java:131-132` re-pins only `@maven_upstream//:pin`. `@maven_runner` (`MODULE.bazel:228-230`) is also keyed on `LEGEND_ENGINE_RELEASE` and has its own `maven_runner_install.json`. After a bump that lock no longer matches the requested versions.
- This adds to K10.
- **Fix:** re-pin every pool derived from the release (or derive them from one pin target). Add a test that every lock's coordinates match MODULE.bazel.

### N6 · P1 · Embedded Postgres binaries are chosen by host OS; there is no platform gating

- **Evidence:** `tools/postgres/postgres.bzl:23-32` picks the binaries from `rctx.os` (the host) and calls `fail()` for any unlisted host. `//pct:pct_postgres` (`pct/BUILD.bazel:164-172`) is not `manual` and has no `target_compatible_with`.
- **Impact:**
  - `bazel test //...` fails while fetching on unlisted hosts (e.g. linux/ppc64le, windows/arm64).
  - Under remote execution where the exec platform differs from the host, the test receives the wrong OS's binaries.
- **Fix:** declare one `http_archive` per platform and select through an `alias`/`select` on `@platforms` constraints (or a toolchain). Put `target_compatible_with` on `pct_postgres*`.

### N7 · P2 · Problems in `testing/.../EmbeddedPostgres.java`

- Port race: `:91-94` binds `ServerSocket(0)`, closes it, then starts Postgres on that port. Parallel tests can collide.
- `initdb` refuses to run as root, so Linux CI containers that run as root will fail.
- `:152-167` is a third hand-rolled runfiles resolver (alongside `Repo` and `Upstream`).
- `:58` stops the server from a shutdown hook. When Bazel's timeout SIGKILLs the JVM, `postgres` is orphaned.
- `:88` falls back to `java.io.tmpdir` when `TEST_TMPDIR` is unset.
- **Fix:** retry on bind failure; use the rules_java `Runfiles` library; keep the cluster in `TEST_TMPDIR`; stop it in a JUnit extension rather than a shutdown hook.

### N8 · P1 · JUnitMain does not speak Bazel's test protocol

- **Evidence:** `tools/junit/JUnitMain.java:56-58` writes reports to `$TEST_UNDECLARED_OUTPUTS_DIR/junit` and ignores:
  - `XML_OUTPUT_FILE`, so Bazel's `test.xml` has no testcases and BES/CI cannot show which test failed;
  - `TESTBRIDGE_TEST_ONLY`, so `--test_filter` is silently ignored;
  - `TEST_TOTAL_SHARDS` / `TEST_SHARD_STATUS_FILE`, so sharding is impossible;
  - `TEST_PREMATURE_EXIT_FILE`.
- **Fix:** write the console launcher's legacy XML to `$XML_OUTPUT_FILE`, map `TESTBRIDGE_TEST_ONLY` to selectors, and implement sharding. Alternatively adopt contrib_rules_jvm's `java_junit5_test`.

### N9 · P1 · PCT pass/fail depends on which test classes share the JVM

- **Evidence:**
  - `pct/.../PctCensusGate.java:16-27,37-53` says outright that its counters are cumulative per JVM and the pins "only move on the unfiltered gate command's numbers". `pct/BUILD.bazel:88-91` says the same.
  - Every `ChannelB*Test` asserts the cumulative `SqlTypeCensus` / `CanonicalDivergence` counters, e.g. `ChannelBEssentialTest.java:207,244,255-267`.
  - `Corpus.UNREADABLE` / `DEDUPED` are mutable statics (`parser-equivalence/.../Corpus.java:112-116`).
- **Impact:** the manual per-suite targets (`pct_duckdb_<suite>`, `pct_postgres_<suite>`) run under different ceilings than the combined lane. `--test_filter` or sharding would change what is being measured.
- **Fix:** reset the counters per suite and assert per-suite deltas, or give each suite its own target with its own measured ceilings.

### N10 · P1 · ChannelB loads sources in filesystem order

- **Evidence:** `pct/.../channelb/ChannelB.java:105-113` calls `Files.walk(root)…toList()` with no sort. That order feeds the parse ("first definition wins") and the wall-dropping loop at `:124-160`. The wall counts and exact discovery counts are pinned (`ChannelBEssentialTest:44,60`).
- **Impact:** results can differ across operating systems and filesystems.
- **Fix:** sort by the `/`-separated relative path, as `MinimalCorpus.sortKey` does.

### N11 · P1 · MinimalCorpusTest asserts wall-clock time

- **Evidence:** `spec/.../rcorpus/MinimalCorpusTest.java:53,379-385` fails if any corpus test takes more than 60 s. That depends on the machine, its load, and remote executors. The check is skipped when the undeclared env var `LL_SHADOW` is set.
- **Fix:** let Bazel's `timeout`/`size` handle runaways, or move timing to a perf lane. Declare any switch with BUILD `env`.

### N12 · P1 · Goldens and ledgers are updated by hand, not by `write_source_files`

- **Evidence:**
  - `spec/.../generators/ReferenceLaneTest.java:42-44` says to bless a change with `unzip -o -j bazel-testlogs/spec/reference_lane/test.outputs/outputs.zip core_relational.txt -d spec/src/test/resources/reference-lane/`.
  - The 29 roster/register files in `spec/src/test/resources/rcorpus/*` are hand-edited from the test's LOST/GAINED output (`MinimalCorpusTest.java:977-990,1069-1080,1144-1157`).
  - Ratchet constants live in Java source and are edited by hand: `DISCOVERED/DECLARED/EXCLUDED` and `*_STRENGTH` / `*_TEXT_DECIDED` / `*_LENIENCY` (MinimalCorpusTest); `OwnCorpusParityTest.MIN_MATCHED`; `CorpusSweepTest` `MIN_*/MAX_*`; `ImplementationTableTest:112`; `CatalogUpstreamDiffTest:200-202`; `SubsumedRegistryTest:28`; `DynaFnRegistryTest:50`; `UpstreamPathManifestTest:54`; ChannelB discovery/pass pins; `PctCensusGate`; `PctDisciplineTest:64`; `RejectionParityTest`; `SectionParseSentinelTest`; `MutationFuzzTest:38`; `FixtureAdjudicationTest`; `OwnDialectCensusTest`.
- `ReferenceLaneTest.java:89` hard-codes "legend-pure 5.99.0 / engine 4.145.0" into the golden's header, so it goes stale on every bump.
- **Fix:** make each measurement a build action (`java_run`) that emits the report or roster. Commit and diff-test it with `write_source_files`, so `bazel run //:update_generated` is the only update path. Read version strings from `oracle-pins.env`.

### N17 · P2 · The fixture harvest depends on classpath order to shadow upstream classes

### N21 · P2 · Census tests over other modules' source trees couple the modules

- **Evidence:**

  - `OwnCorpusConformanceTest:226-262`, `OwnDialectCensusTest:85-136` (per-host pins) and `FixtureAdjudicationTest:321-342` work the same way.

### N22 · P2 · The core layering check is a hand golden plus a duplicated list
