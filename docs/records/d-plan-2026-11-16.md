# D, end to end: everything compatibility-related to the edge (plan, 2026-11-16)

Written by the D worker at the orchestrator's request of 2026-11-16. That request carried the user's
words: "set up a full end to end plan that we can go over clearly and then execute on them and keep
going don't stop until done".

Once the user approves this plan, it is D's whole scope. Anything new goes on the parking list (§9)
unless it blocks the outcome.

## 1. Outcome

In the user's words: "everything compatibility-related to the edge". The product does everything
typed, fast and cheap. Backwards compatibility stays as close to legend-pure and legend-engine as
possible, and lives at the edge.

What is true for a user when D is done:

- **A product query** (the browser tab, Python, the server's own routes, a plan) answers in lite's
  own typed forms:
  - a Float in six trimmed decimals;
  - a DateTime in ISO 8601 with Z;
  - a cell's, list's or relation's text in lite's form, or refused by name;
  - an error as its kind and where it happened, worded from the plan.
  None of legend-pure's or legend-engine's spellings is computed for it, in SQL or in Java.
- **A legend-engine client** (pure/v1 execute, generatePlan, a PCT run, the relational corpus, an
  engine-style service test) gets exactly what legend-pure and legend-engine give. That comes from
  the edge (`com.legend.edge`, the edge dialects and hooks), which the product never reaches.
- **The line is mechanical.** A test fails if a compatibility spelling appears in product code.
  Every deliberate difference from upstream is a row in docs/SEMANTICS_REGISTER.md that the user
  ruled.

Recommendation: **(a)**.

**U2: The bundle budget.** RULED (a) by the user, 2026-11-16, relayed by the orchestrator:

- raise the grid budget by about 800 bytes and the engine budget by about 150;
- each raise carries a dated note naming the ruling.

**U3: Huge Floats where a database can't give the shortest digits.**

W3 aims for one answer everywhere. If a database (MongoDB's Decimal128, ClickHouse) can't produce
the 17-significant-digit shortest form cheaply:

| Option | Cost |
|---|---|
| (a) Refuse values of magnitude ≥ 1e15 on that database, by name | Nothing per row |
| (b) Print its own digits, with an S311 divergence row | Nothing per row |
| (c) Exact through a text round-trip | About 2–3x the per-row cost of the Float print on that database |

Recommendation: **(c)** where the cost is under 2x, else **(a)**. I would post the measured residue
before it lands, as this decision allows.

**U4: The judges (W10). May a judge row that cannot move stay?**

PCT's judges compare pure's forms (FLOAT_CANON, Repr). Moving them behind a lowering hook keeps PCT
identical.

| Option | Implication |
|---|---|
| (a) All move; no exceptions | May cost W10 more hours (+10) if one resists. |
| (b) Pre-approve an exception list | Rows that stay are named in v1's PR, the guard keeps them as STAYS, and you rule them in review. |

Recommendation: **(a)**, with (b)'s list in hand only if W10 overruns by more than 10 hours.

**U5: Exceptions to the guard.** RULED by the user (relayed by the orchestrator, 2026-11-16).

Verbatim, 2026-11-15: "We should look at dataformats and tsshow to see if really need those
