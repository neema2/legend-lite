## SHOULD 2: a planner's wrong counts said once, by name

`tab-data.ts` `tables()`: the per-row `try` wrapped the plan's lookup, so a planner answering fewer counts than tables
showed a TypeError as "count failed" on every row. The answer is now checked before the loop: one plan of one statement
per made table, or one refusal naming what came back. The plan is taken out of `counts` outside the `try`, whose catch
covers only the run and the no-count check.

Red on revert: `engine-client/test/model-data.test.ts`, "a planner answering the wrong counts is refused by name",
fails with "Missing expected rejection".

## SHOULD 4: an undeclared npm package

esbuild finds an undeclared npm package as it finds an undeclared module: through the real output tree. Until now the
check skipped every read under `node_modules/`.
- Each bundle's list of declared files now carries its directories, the npm packages' tree artifacts, with a trailing
  `/`, and an external repository's files under `external/`.
- The test takes a read under a declared directory as declared, and checks every other read. Nothing is skipped by
  path any more.
- All 15 bundles pass, so every npm package a bundle reads is one it declares.
- The plant: a declared package's file passes. An undeclared package's file is named, and so is a package whose name a
  declared one's directory only prefixes (`apache-arrow/` declares nothing of `apache-arrow-extra/`).

Red on revert, both ways:
- The test skipping `node_modules/` again fails the plant.
- The rule listing no directories fails the real check (e.g. "@@//datacube:widget reads
  datacube/node_modules/.aspect_rules_js/echarts@6.1.0/node_modules/echarts/core.js, ...").
