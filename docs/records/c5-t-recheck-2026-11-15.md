## The fold-in review's item 1: a planner worker that stops

This PR made the workspace's tables take one step at a time (MUST 2 above). Studio's planner answers in a worker
(`WorkerPort`, `engine-client/src/legend/wasm-grammar.ts`), and the port had no `onerror`. A worker that died left its
request unanswered, and that held every later load, put, reset and table list behind it. This was a regression of this
PR, so it is fixed before the merge (the orchestrator, 2026-11-15).

- The port now handles `onerror` and `onmessageerror`. A failing worker stops: every waiting request is refused by name
  ("the planner worker stopped: <its message>"), every later request is refused the same way without a post, and the
  worker is ended. The error is answered by the port (`preventDefault`), not left to the page.
- What the refusal says:
  - An uncaught error: its message, and its file and line when the event carries them.
  - A script that fails to load (a bad deploy, a wrong or blocked URL, a module that will not link), the likeliest
    case: the browser fires a plain Event with no message, so the port names the worker. "the planner worker stopped:
    the worker at <its URL> failed to load or run" (the orchestrator's check, 2026-11-15).
  - An answer the worker could not hand back: "an answer it could not hand back".
- The chain moves on. The waiting step rejects, the next one rejects, and a step that asks the worker nothing runs.

Tested in `engine-client/test/model-data.test.ts`, "a planner worker that stops":
- On the port: two waiting requests and a later one are refused by name after an error with a file and line; a waiting
  request is refused after an answer the worker could not hand back; and after a plain Event, the worker is named.
- Through `TabTables`: its counts asked of a fake worker, a table list waiting, one behind it and a load behind both.
  The two lists reject by name, and the load runs.
- The fake dispatches as a browser does: to the handler if one is set, else to no one. Each wait is bounded by the test
  alone (5 s).

Red on revert:
- Without the two handlers, both tests fail with "still waiting after 5000 ms".
- Without the file and line, the first assertion fails ("... out of memory" for "... out of memory
  (http://planner.invalid/planner-worker.js:12)").
- With "an error it did not name" back for a plain Event, the load case fails.
