## 2. Registered, not changed

- **Several rows writing one property from itself** (S98): fixed by the second review (§6): refused by name.
- **`ON CONFLICT DO NOTHING` with one key twice in the rows** (S103): both rows are written (the key's error) where
  Postgres keeps the first.
- **A NULL merge key** never matches: each merge of it inserts (the database's `MERGE`;
  `docs/WRITES_FOR_STORE_BACKENDS_2026_10_22.md` §4).

## 3. Not reproduced

- `#SQL` RETURNING over a plan's parameters: the island has no `$` parameter syntax, so the case cannot be written.

## 4. Decisions for the user

1. **S98, several rows writing one property:** decided (the owner, 2026-10-24): raised by name (§6).
2. **Domain ids:** the domain writer emulates the native store's `nodes`/`rels` by id, so a model whose classes share ids
   is refused for MERGE, DELETE, REMOVE and read-back SET (fix 9). The full fix keys the emulation by identity
   (`class:id`) throughout: a redesign of the writer's graph-A half.
3. **Store writes and the session's dirty mark:** a program's writes do not mark the session dirty (the design says
   product writes are never wiped); confirm.
4. **Graph A's write models are inferred from Neo4j's after-graph** in the domain lane (decision D8's spirit: the judge
   should not shape the model under test); confirm or move the inference to the before-graph plus the statement.
5. **Id minting** (S100: max + row number, unsafe under concurrent writers) versus an identity or sequence column.
6. **Postgres's upsert:** `MERGE` (PG15+) versus `INSERT ... ON CONFLICT` (any PG with a unique index).
7. **RETURNING** reads rows staged before the write: a column the write computes (a default, a trigger's) is not seen.
8. **One write path:** the execution path (`StatementExecutor`) and the plan path (`PlanMaker`/`PlanRunner`) both run
   writes; whether execution should run the plan.
9. **Staged-table names** are the let's (`legend_stage_<let>`): two islands staging one let name in one program, or
   two programs in one caller's open H2 transaction, collide (the database's error).

## 5. Deferred work (not in this PR)

- The Cypher `Writer` as its own class (it is a large inner class of `CypherToPure`).
- `UPDATE` and `DELETE` skip the dialect's render passes that `SELECT` gets; a pass that matters to DML would be missed.
- Write plans hold SQL text only (no typed tree in `PlanJson`).
- `JavaEvalLedger`'s `StatementExecutor` pin grew with the write arms; the residue should shrink with decision 8.
- The direct-mapping rule "one table per class" is not checked against two classes sharing a table.
