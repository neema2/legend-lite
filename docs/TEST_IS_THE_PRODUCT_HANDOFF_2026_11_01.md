## 0. In two paragraphs

legend-lite runs a Pure test body two ways. **The walk** (`driver/BodyCompiler` + `driver/BodyDriver`, behind
`Execution.runProgram`) takes a body statement by statement, planning each in the driver as it goes and running it at
once (host judge) or deferring its verdict into a fused statement (database judge). **The program road** plans a
body WHOLE through the product's planner (`testplan/TestDoor` -> `planner/PlanMaker.testProgram`, the test's own
kinds planned by `testplan/TestKinds` through the planner's extension point) and runs it as one plan
(`exec/PlanRunner.program`), its verdicts and answer delivered to a sink. The program's goal (the user's): **the test
is the product** -- every test body runs on the product's road, and the walk and every bespoke test path are deleted
(M10). Bodies move class by class (R16): `driver/BodyRouter` asks `testplan/BodyClass` for a named class over the
body's typed shape; a body of a moved class is planned by the test door and run as one plan, every other body is
walked.

Done and pushed: M0, M1, M2, M3, MR, M5 (two classes moved: `EFFECT_PROGRAM`, the corpus setup programs, 604 bodies
per corpus pass; `QUERY_PROGRAM`, plain query programs), the upstream answer facts (R21). M4 is DEFERRED by the user
(R23). **M6 is half-built**: the host judge's asserts split into a plan half and a judgment, and a third class
(`ASSERT_PROGRAM`, host judge only) moving whole; quick tests and the router parity test green; the measurement chain
and the independent audit were running when this was written (their results are NOT recorded here: re-run them).

## 4. M6 in detail

### 4.1 The design (what the code on the -wip branch does)

The host judge's arms planned in two halves; the walk runs both halves back to back (no behaviour change); the
program road plans the first half before the program and judges with the second at the verdict step.

1. **`driver/HostSides`**: `Check(asks, judgment)` -- an arm planned: the sides it asks for (`Ask`: the argument, the
   identity lane, the fold, the splice hook) and a `Judgment` over the shaped sides (`@Nullable TypedSide judge(List<TypedSide>)`,
   null = the arm declines the sides it read). `run`/`judged` (the walk: fetch, then judge), `plan` (the sides planned
   as one verdict's base: `Planned(sides, base, on)`), `shaped` (the runner's rows shaped by position, the to-one
   reader's check where a side was sent), `fetch` = plan + run + shaped.
2. **`driver/HostJudge`**: every single-fetch arm became `planX(...) -> Check` plus its walk form
   `X(...) = HostSides.run/judged(name, planX(...), ...)`: tdsEquivalent (NOW one fetch of grids + tolerances, the
   walk fetched them in two runs: same statements in the same order; differs only where the grids are not tabular and
   the tolerances are not literals -- expected 0), size, contains, tolerance, condition (forAll-contains or the
   identity lane), empty, eq, instanceOf, is (null where the pair is not two elements), sameElements, equals,
   jsonStringsEqual, rendered, and the grid pair (`planGridPair`, moved out of `AssertVerdicts.adjudicate`'s inline
   code). Not split (two stages or not needed yet): `cellPool`, `quantified`, `quantifiedRows`.
3. **`driver/AssertVerdicts.planHost`**: `adjudicate`'s dispatch mirrored for the shapes it plans, returning
   `HostAssert(listenerName, @Nullable family, wantEqual, check)` or null for: lineage lines, the quantified forms
   (TypedMap, forAll), `assertSameSQL`/TDG/dual-golden roots, `SqlTextVerdicts.mayArm` (a static superset of the
   engine-text arms' gates: a toSQLString producer, a generator's fetch text, a SQL read, a plan node's read on either
   side), the sorted cell pool, arity misses. In **HOST mode only** (`JudgeMode.HOST`; BOTH is AgreementArm, untouched)
   `adjudicate` tries `planHost` first and runs it in place (`HostAssert.run`: `enter()` counts the family before any
   side, `judge` counts `sqlFellThrough` on a null). Census calls stay inside `AssertVerdicts` (ArchUnit's V3 rule,
   `hostVerdictIsReachableOnlyFromTheVerdictSeam`, allows only the seam classes to touch `CanonicalDivergence`; nested
   classes and the router are not exempt, so `familyEntered`, `judgedOrFellThrough`, `judgedAtItsStep`, `sideRefused`
   are `AssertVerdicts` statics). `HostAssert.raising(...)` = an assert whose planning raised, raised at its turn.
4. **`driver/HostAsserts`** (new): every assert of an `ASSERT_PROGRAM` body planned BEFORE the program, as the walk
   plans it: the walk's environment (`BodyDriver.bodyEnv`, factored out of `BodyDriver.execute`), the walk's let
   prefix (every non-last let: `registerHandlesIn` then the prefix; a copy per assert, since the judgment reads it
   after the program ran), `frameReplaceEnv`/`spliceHook` with no frames, `planHost`, then `HostSides.plan`. A
   classification or side-planning exception becomes `HostAssert.raising` (the walk raises it at that turn, after the
   earlier asserts ran and reported: the parity test caught this). Null (the walk) where an assert's shape is one
   `planHost` does not plan. Implements `TestDoor.Asserts` (statement index -> its `Verdicts` step); `of(verdict)` by
   identity.
5. **`testplan`**: `TestDoor.Asserts` (the hook; `NONE`), `TestDoor.planned(..., asserts)`; `TestKinds` places a
   statement-root assert's step from the hook (else the refusal names "M6-M8: an assert its judge planned no verdict
   step for"); `BodyClass.ASSERT_PROGRAM` and `of(body, runtime, hostJudge)`: statement-root asserts (at least one),
   non-last statements that plan no step or lets of `LetPlanner.Kind.VALUE`, nothing planned another way (the query
   program's list: execute, staged rows, raw grids, store writes, system store, objects built, graphs, temporal reads,
   packageable refs -- so `assertIs(Integer, Integer)` stays walked), no TDG, no seeds, and the LAST statement an assert
   or a statement that sends nothing (a query planned after the asserts could fail its planning before they ran).
6. **`driver/BodyRouter`**: under the host judge, `BodyClass.of(..., hostJudge)`; for `ASSERT_PROGRAM` the asserts are
   planned first (`HostAsserts.plan`), null -> the walk; the `Moved` sink judges at `sides(verdict, rows)` via
   `AssertVerdicts.judgedAtItsStep` (tryAdjudicate's listener and census protocol: sqlEnter, family, verdict reported,
   AssertFailed/DataError -> sqlRaised + unjudged + verdict false, any other exit -> sqlRaised) and `sidesFailed` via
   `sideRefused`; a judgment that declines (null) is refused by name (`NotImplementedException`); a body ending on an
   assert answers `JudgePlans.host(lastVerdict, answer)` as the walk does; `plan.answers()` guards the early sink.
   `verdict`/`fused` still throw (the database judge's bodies are M7's).
7. **`exec/PlanRunner`**: `ProgramSink.sidesFailed(verdict, DataError)` (default returns the error); HOST sides read in
   `hostSides` under a catch; `databaseVerdicts` split out; `constantsAlone` now runs a verdict group of constant sides
   with no session (HOST: the sides to the sink; DATABASE: a null row). **`executionplan/ExecutionPlan.answers()`**
   (a program ending on an assert answers nothing). **`planner/PlanMaker.sqls`** lists a verdict group's statements.
8. Tests: `BodyRouterParityTest.assertPrograms` (12 bodies on every in-process backend whose type Pure's
   `DatabaseType` names: outcome, ledger, answer, statement origins, effects census, database left, statements in
   order, the listener's verdicts and the verdict census, compared walk vs router) and the class pins; `BodyClassTest`
   MOVED += ASSERT_PROGRAM (dated); `TestDoorTest`'s refusal text; `CodeShapeGuardrailTest` allowlists
   `BodyRouter.lastVerdict` (dated 2026-11-01, M6).

## 8. Lessons and traps (each one cost a cycle)

1. Statement-origin labels are part of the measurement: on the program road a `TdsResult`/`Keyed` answer step is
   marked `enterIfUnmarked(STATEMENT)` by the runner; an effect script `BODY` around its send only; seeds `SEED`.
   M5d's first try shifted labels; match the walk's.
2. Test code must not name a database outside its owners (`DialectLeakRatchetTest`): go through `TestBackends`.
   SQLite is not in Pure's `DatabaseType`: the parity test filters backends by the enum's values.
3. `testplan` has no `:resolver` dependency (use `Pure.Lite.STAGE`); `testplan` may not depend on `driver` (the driver
   depends on it): hooks go testplan -> interface, driver implements (`TestDoor.Asserts`).
4. Guards: `JavaEvalLedgerTest` pins line counts per registered class (re-pin with a dated reason); the mutable-field
   guard (`CodeShapeGuardrailTest`) sees every non-final instance field (allowlist with a dated reason); ArchUnit V3
   keeps `CanonicalDivergence` to the verdict seam's classes (nested classes are NOT exempt); the salted-order guard
   bans `Set.copyOf` (use a LinkedHashSet); NullAway on every library; the parser-equivalence ratchet is regenerated
   with `bazel run //parser-equivalence:update_ratchets` when a corpus count moves (3036 -> 3038 at M5).
5. `ExecuteOptions.JudgeMode` is HOST, DATABASE or BOTH. Channel B (`pct/.../ChannelB.java`) judges BOTH
   (`AgreementArm`); the corpus has four passes (database/host x DuckDB/H2); PCT DuckDB and most core tests default
   to HOST. A HOST-only change must test `== HOST`, never `!= DATABASE`.
6. A record compares by value: key per-verdict judgments by identity (`IdentityHashMap`), two equal asserts are two
   verdicts.
7. A program ending on an assert has no answer step: `ExecutionPlan.answerShape()`/`sendsTheAnswer()` throw on it; ask
   `answers()` first. A program whose verdict sides are all constants has no target: `PlanRunner.constantsAlone`
   handles it.
8. The router may decide only by a static rule; a planning failure is not a routing signal (R16). Where planning a
   moved body can fail, plan the failure as a raise at its turn (M6's `HostAssert.raising`), which is the walk's
   behaviour and MV8's pattern.
9. The walk's census and listener protocol is observable (the corpus prints it; the parity test compares it): any new
   path must count `sqlEnter`, the family, routes, `sqlRaised`/`sqlFellThrough` exactly where the walk does.
10. CI: a stress-lane runner disk failure is infrastructure (a re-run once; a 403 means no re-run rights: comment
    once on PR #83, keep watching). A revert, reset or force push of `main` is never a session's call.
