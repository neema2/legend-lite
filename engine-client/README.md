# engine-client

Where a query runs, for every app here (DataCube, Query, Studio). It was moved out of `datacube/src/` on
2026-10-04 so the apps share it instead of reaching into one another. "Engine" means any place a
query runs, not only legend-engine. Like `sdlc-client/` and `depot-client/`, it holds the client of a
server and the same thing answered in the page.

| File | What |
|---|---|
| `engine.ts` | `QueryEngine`: the one interface every place a query runs implements |
| `relation-type.ts` | A plan's columns and their types |
| `result.ts`, `receipt.ts` | What comes back: columnar raw values; what ran it, where, as whom |
| `values.ts`, `types.ts` | A cell's exact stored value; the one reader of a column's type |
| `generated/lite-facts.ts` | legend-lite's type families, generated by running legend-lite (`bazel run //engine-client:update_generated`; a diff test holds it) |
| `pure-v1.ts`, `engine-remote.ts` | legend-engine's `pure/v1` client (legend-lite's or upstream's), and executing on it |
| `duckdb.ts`, `duckdb-wasm.ts` | DuckDB in the tab: the engine, and the package re-exported for an app's boot |
| `warehouse.ts` | The warehouse (DuckDB on a server): sign-in and execution, Arrow results |

Its npm packages are its own lock (`npm_engine_client`): DuckDB-WASM and Apache Arrow. Apps import
DuckDB-WASM from `duckdb-wasm.ts`, never directly. That way every bundle carries one copy of Arrow,
the one the warehouse reads with too. DataCube's bundle budget test holds that.

An app embedding DataCube's grid imports `datacube/src/embed.ts`, DataCube's one public entry.
