# THE HOST-SQL GUARD'S RULE (docs/ONE_PLATFORM_PROGRAM_2026_10_12.md D5, the dialect program's decision D5): no product
# source of the tab's apps and the libraries they bundle (HostSqlTest.java) or of Python's host (python/legend_lite:
# python/tests/test_host_sql.py) spells SQL. A host names an operation and its data; legend-lite's planner writes the
# statements, by the database's type (core's sql/dialect/HostOperations.java). Each half reads its language's string
# literals -- never comments, never Python's docstrings -- and fails on one that begins a statement: a keyword below,
# upper case, then a space; or a lower-case statement's shape. A site kept is named with its reason.
#
# What it holds is the literals a host writes: a statement built from parts none of which begins one ('DROP' + ' T')
# is not seen, and the three operation fields that carry SQL (a source query, a select list, a conversion) carry the
# planner's text, read from its answers.
#
# Sections: [typescript] and [python], the folders each half reads (every .ts but .d.ts under one; every .py in one);
# [keywords]; [shapes], each a regular expression a literal's text may not begin with (Java's and Python's alike);
# [kept], each `file | the literal's whole text, in double quotes (\" and \\ its escapes) | why it is not a statement
# the host spells`.
# [harnesses] (2026-11-12, the C final audit's H12: the census read .ts alone, and the JavaScript harnesses beside the
# demos sent their own statements unseen; it reads .mjs, .cjs and .js too): each `file | why`, a harness script kept
# whole -- a test in all but its folder, run by hand or as a browser test, whose statements build its own fixture
# database or stand for a person typing; any other script spelling a statement is red, and one kept that spells none is
# stale.
